# Design-sync notes — admin-frontend

## Scope (first sync, 2026-09-17)

Only 12 of the 64 components in `components/ui/` were synced, by explicit user choice ("less is more" — keep the first import small): Button, Input, Label, Textarea, Checkbox, Switch, Badge, Card, Separator, Avatar, Select, Dialog. The rest can be added later by extending `componentSrcMap` in `config.json` and `pkg-entry.mjs`.

## Non-obvious setup

- **No dist build exists for this DS** — it's the app's own `components/ui/`, not a publishable package. `.design-sync/pkg-entry.mjs` is a hand-written entry that re-exports exactly the 12 scoped components (and their sub-parts); `cfg.entry` points at it. Extending scope means adding exports there too, not just to `componentSrcMap`.
- **Tailwind v4 must be compiled before every build.** `app/globals.css` is raw Tailwind v4 source (`@import "tailwindcss"`, `@theme inline`, etc.) — the design-sync converter only copies CSS verbatim, it doesn't run Tailwind's engine. `node .design-sync/tw-compile.mjs` (the `cfg.buildCmd`) runs `@tailwindcss/postcss` directly and writes the compiled output to `.design-sync/.cache/compiled-tailwind.css` (gitignored — regenerate it, don't expect it to survive a fresh clone). `cfg.cssEntry` points there. **Always re-run this before `package-build.mjs`** if any Tailwind class usage anywhere in the app changed (the compile scans the whole repo, not just the 12 components) — a stale cache silently ships old styles.
- **Fonts (Inter, JetBrains Mono) are not in the repo.** They're loaded via `next/font/google` at Next.js build time (self-hosted, no static `@font-face` file to reuse). Fetched from Google Fonts' CDN instead (latin subset only, both open-source: Inter = SIL OFL, JetBrains Mono = Apache 2.0) into `.design-sync/fonts-src/` — this IS committed (unlike the Tailwind cache) since it's a one-time fetch, not a rebuild output. User explicitly approved fetching from Google Fonts as the resolution for `[FONT_MISSING]`.

## Re-sync risks — read before trusting a clean re-sync

- **Render check and screenshot-based grading were never machine-run.** No playwright/chromium was installed (user declined the ~200MB download) — both `package-validate.mjs --no-render-check` and `package-capture.mjs` (which also needs a browser) were skipped. Verification for this sync was **human-only**: all 12 previews were reviewed live via `.review.html` and confirmed correct by the user. If a future re-sync has playwright available, a first full `--render-sample 0` pass to establish a real baseline would be worth doing.
- **`Select` and `Dialog` previews assume base-ui's `Root` supports `open`/`defaultOpen`/`onOpenChange`** (used to force the open state in `.design-sync/previews/Select.tsx` and `Dialog.tsx`). This matches the standard base-ui/Radix-family API but was not independently verified against `@base-ui/react`'s shipped types (no reliable `.d.ts` extraction — see below). If a re-sync ever shows these previews broken, check this first.
- **Per-component `.d.ts` prop extraction failed for all 12** (every component is a plain function with an inline destructured parameter type, not a named/exported props interface — ts-morph's extractor couldn't resolve any of them, silently, with no `[DTS_PARSE]`/`[DTS_STYLE_SYSTEM]` warning). Every component's real prop contract is hand-written in `cfg.dtsPropsFor` instead, derived by reading the source directly. If the source changes (new variant, new prop), `dtsPropsFor` will silently go stale — there's no automated check tying it back to the `.tsx`.
- **`[TOKENS_MISSING]` warnings are expected, not a bug**: `--toast-index`, `--ratio`, `--accordion-panel-height`, `--header-height`, `--popup-height`, `--positioner-height`, `--available-height`, `--anchor-width` are all set at runtime by `@base-ui/react` (inline styles for popover/positioner sizing) — none of the 12 components need them defined statically.
- **The compiled Tailwind CSS (`.design-sync/.cache/compiled-tailwind.css`) is scoped to the whole app**, not just the 12 synced components — it's larger than strictly necessary but guarantees every class the previews use is present. No action needed unless bundle size becomes a concern.
